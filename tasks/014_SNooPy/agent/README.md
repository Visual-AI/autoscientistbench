# SNooPy variant-calling benchmark

## 1. Goal

**Research question.** A metagenome mixes strains of one species at unknown number and abundance, and long reads are noisy. How well can SNPs between strains be separated from sequencing errors, without assuming ploidy or a number of haplotypes?

**Experiment.** The SNooPy paper (Faure et al., Nucleic Acids Research, 2026) compares SNooPy with bcftools, Longshot, NanoCaller, DeepVariant and Clair3, all run with recommended or default options, by the F1 of their calls against truth from known genomes. This task is one setting of its Fig. 3(ii), which varies the read error rate: a simulated mixture of four E. coli strains at 20x coverage each, a 5% read error rate, and variants called against a metaFlye assembly.

**Task.** Call variants in the fixed, existing noisy long-read alignments against their observed assembly and maximize SNP F1 on held-out contigs. The supplied SNooPy Fig. 3(ii) baseline is training-free. No new reads or biological sequences are generated by this task.

## 2. Data

data/train/ contains only a training-free note. There is no training split: validation may be used for evaluation and selection, and no reusable model or learned preprocessing may be fitted on it. data/val/input/ contains the observed assembly, sorted indexed BAM, and contig manifest; data/val/labels/ contains separate truth call files. Validation uses 18 contigs and 1,136,742 assembly bases. The remaining contigs from the same fixed dataset are held by the judge. The partition uses a fixed label-independent hash of contig IDs. Every original mapped alignment belongs to one full split. Read names are anonymous, and simulator identity and program-command metadata are removed. Do not re-split, relabel, generate new observations, or add outside data (patch audit).

## 3. Metric and scoring

snp_f1 is higher-is-better: harmonic mean of precision and recall from the authors' count_number_of_missing_variants function (bench/authors_metric.py), and zero when both are zero. Recall is the share of positions in the pre-existing few-call truth that are called. Precision is the share of called positions found in the many-call truth. Both truth sets are pileup calls of the strain genomes aligned to the assembly, few-call under strict alignment settings and many-call under permissive ones (code/evaluation_scripts/evaluate_vcf_with_solution.py).

Scoring is by equal-length-substitution positions. A record counts if any ALT has the length of REF and is not "."; it then marks every position REF covers, and the allele itself is not compared. Contigs absent from the few-call file are skipped, so calls on them count neither way. The paper excludes variants longer than 5 bases from its analysis, but the evaluator has no explicit cutoff; its exact existing logic is preserved.

Scorer checks: malformed predictions, reported CPU allocation above 32, or failed calling yield zero. Elapsed time is not a guard, the scorer does not read max_calling_seconds in the labels manifest, and train and predict have no separate wall-time cap; one overall deadline covers the judge's replay. Judge enforcement: CPU affinity is limited to the allocated 32 CPUs. Patch audit: the candidate must actually call variants and report complete honest timing and CPU metadata; the output-only scorer cannot authenticate these reports or the source digest. Fixed observed data and no cached predictions are protocol requirements that also rest on patch audit.

## 4. Baseline

The editable official implementation is code/snoopy.py, upstream commit 645a39fe16e7ee514ec6a84b44a6819d2b911f5b from https://github.com/rolandfaure/SNooPy. The adapter supplies indexed observations, --benchmark, the existing default caller settings, seeds and allocated threads. It invokes the current candidate source. The caller itself is unchanged.

SNooPy assumes only that sequencing errors occur independently across reads, so alternative bases shared by the same reads at several loci indicate a real strain; it assumes nothing about the number of haplotypes, their relationships or their divergence. In each window it keeps loci with an alternative allele in more than 5% of reads, clusters correlated columns, and accepts a pattern of a reads sharing b loci, among n reads and m loci, when s^(ab) C(n,a) C(m,b) is below 0.001. The paper sets the error bound s at three times the divergence measured from the alignments. Rescue steps recover isolated SNPs, high-noise correlated loci and secondary alleles.

Measured baseline on validation at 32 CPUs and seed 1: snp_f1 mean 0.8679, std 0 (one seed), precision 0.8292, recall 0.9105, 8,599 truth positions, 10,608 called positions. Training takes 0.06 s and validation prediction 81.56 s.

## 5. Interface (frozen)

bash code/train.sh --out DIR saves method artifacts (the baseline writes a training-free marker). bash code/predict.sh --model DIR --input PATH --output FILE executes the caller and writes the JSON/VCF prediction specified in bench/io_spec.md.

BENCH_SEED, BENCH_CPUS, BENCH_DATA_DIR, BENCH_BENCH_DIR, and BENCH_RUNTIME_DIR are supplied by the harness. Python and command-line dependencies are in the read-only runtime (Python and biotools prefixes). code/env.lock is immutable: bench submit rejects a changed lock, so dependencies cannot change. bench validate-output FILE checks a prediction file.

## 6. Rules

The research scope below determines which components may change. Supplied data and splits, trusted tests, information boundaries and the evaluation metric remain fixed.

Candidate source under code/ is editable, including the caller; preserve train/predict signatures and output schema. Data, scoring code, README, runtime and environment lock are frozen. Calling must use the supplied observations with honest resource metadata (patch audit). Do not read hidden labels, cache known predictions, memorize paper results, bypass the real computation, or access outside sources.

Full execution uses up to 32 CPUs. The memory allocation is 144 GB. There is no network in train or predict. Seed 1 is used for this deterministic, single existing dataset protocol; the adapter seeds Python and NumPy.

## 7. Known pitfalls

Validation and hidden observations are distinct contig partitions. Their dataset-wide error-rate estimates can differ because the unchanged caller estimates this statistic from the supplied BAM. The assembly and BAM must remain indexed; no writes to frozen inputs are needed. Truth files are never caller inputs.

## Research scope

**Objective.** Call SNPs from the existing fixed assembly and noisy long-read alignments, maximizing the original position-count SNP F1.

**Fixed research objects.** supplied assembly, mapped observations, contig partition and fixed truth-comparison semantics; VCF/contig coordinates, complete calling protocol and original precision/recall definitions. The validator and scorer check contigs and coordinates.

**Editable methods.** variant-calling algorithms, statistical estimators, filtering and learned computational components, where any fitting uses only the input being called, at prediction time, and is not carried to other inputs (the baseline's error-rate estimate is an example); training surrogates and equivalent indexing/data-loading implementations.

**Forbidden substitutions.** Implement the calling step in code/: do not run bcftools, minipileup or another existing variant caller from the runtime to produce or filter calls. Do not build in this dataset's number of strains, their abundances, its coverage or its error rate, as constants or as allele-fraction rules derived from them; estimate any such quantity from the input at prediction time. Do not submit a patch whose only change is new values for existing thresholds or constants of the caller. changing the biological reference or observed reads/alignments, generating replacement observations or redefining a true variant; substituting known call tables or removing difficult contigs from scoring; training or fitting reusable model state or learned preprocessing on validation features or labels, including final train+val refits or validation-based distillation. These rest on patch audit.

## Validation use (baseline and candidates)

Fit models and learned preprocessing only on the designated training observations.
Validation features and labels are for evaluation and method, hyperparameter or
checkpoint selection only. This restriction applies equally to the baseline and
every candidate, including final retraining. Do not merge validation into training,
fit normalization/encoders on validation, distill from validation predictions, or
relabel validation observations as training or calibration data.

For tasks defined as per-instance inference, optimization or online interaction,
use only the observation/training/calibration/feedback roles explicitly specified
for that instance. Do not use its evaluation targets or carry fitted state from
validation cases into other independent cases. A development replay directory may
contain separately designated training observations; its validation observations
remain excluded from fitting. Public visibility does not authorize training use.
