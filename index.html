Evaluation protocol

How improvement scores, pass criteria, and isolated hidden-test verification work across all 104 tasks.

Relative improvement toward the target ceiling

For each task, let xi denote the candidate's evaluated metric, baseline denote the reproduced reference implementation, and target_ceiling denote the calibrated upper anchor used to normalize progress across heterogeneous metrics.

Task score = (xi - baseline) / (target_ceiling - baseline) × 100%

Under this normalization, the baseline maps to 0% and the target ceiling maps to 100%. The ratio handles both higher-is-better and lower-is-better metrics uniformly without an extra sign factor. Negative task scores are clipped to 0% before aggregation, while solutions that surpass the target ceiling remain uncapped above 100%.

Collection score = sum of task scores / N

Overall leaderboard scores average across all 104 benchmark tasks. When viewing a single scientific discipline or the discipline matrix, scores average over that discipline's exact task count N, placing every field on the same 0% to 100% scale. Confirmed agent failures contribute 0% rather than omitting failed tasks.

Beating the baseline beyond seed noise

Alongside the continuous improvement score, each task evaluates a strict binary pass verdict governed by its optimization direction, minimum gain margin, and cross-seed baseline variance.

gain = direction × (candidate - baseline) / max(|baseline|, 10⁻¹²) threshold = max(task_delta, 2 × baseline_std / max(|baseline|, 10⁻¹²)) PASS when gain ≥ threshold and the submission satisfies all task constraints.

Here direction is +1 for higher-is-better metrics and -1 for lower-is-better metrics. Submissions that produce invalid output formats, return nonfinite metrics, exceed replay limits, or touch frozen evaluation files cannot earn a pass.

From grounded workspace to hidden-test replay

  1. 1. Grounded research workspace

    Each agent starts inside an executable environment containing the paper context, pinned baseline repository, permitted training and validation splits, and read-only validation scripts.

  2. 2. Long-horizon autonomous optimization

    Within its wall-clock budget, the agent diagnoses bottlenecks, formulates methodological improvements, edits permitted source files, manages dependencies, and validates iteratively.

  3. 3. Clean code patch submission

    Rather than exporting pre-trained weights, the agent submits a self-contained git patch relative to the baseline commit alongside its locked software environment.

  4. 4. Isolated hidden-test verification

    An independent judge rebuilds the environment from scratch, retrains across fixed evaluation seeds, runs inference on held-out test data, and records the final score and pass verdict.
