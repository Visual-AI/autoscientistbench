Evaluation protocol

Visual guide to our two benchmark metrics and the isolated four-stage hidden-test evaluation pipeline.

Improvement score

Normalizes each task from the reproduced baseline (0%) to the calibrated target ceiling (100%), then averages across all N tasks in the selected collection.

Negative task scores are clipped to 0% before aggregation, while solutions that surpass the target ceiling remain uncapped above 100%. Confirmed agent failures score 0% rather than dropping from the denominator.

Pass criteria

A binary verdict requiring statistically meaningful gain beyond both the task margin and twice the baseline's cross-seed standard deviation.

Direction is +1 for higher-is-better metrics and -1 for lower-is-better metrics (denominator floored at 10⁻¹²). Submissions failing any contract check never pass.

Evaluation pipeline

From grounded paper workspace to isolated hidden-test replay across an air-gapped patch boundary.

Agent sandbox Isolation boundary Independent judge
  1. 1. Grounded research workspace

    Starts from the paper context, pinned baseline commit, permitted train/validation data, and read-only validation scripts.

  2. 2. Long-horizon optimization

    Within its wall-clock budget, the agent diagnoses bottlenecks, invents methods, edits permitted files, and validates iteratively.

  3. 3. Clean code patch submission

    Exports a self-contained git diff and locked software environment rather than pre-trained weights.

  4. 4. Isolated hidden-test replay

    An independent judge rebuilds from scratch, retrains across fixed seeds, and scores on held-out test data.
